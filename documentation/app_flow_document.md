# App Flow Document for Thejoflowers-KOS2

## Onboarding and Sign-In/Sign-Up
A new user typically lands on a welcoming page served by the application backend, which immediately presents a clean login form built with ExtJS’s FormPanel. The page includes fields for email and password, a prominent sign-in button, and two links: one to register as a new user and another to recover a forgotten password. When a user clicks the registration link, an ExtJS window slides into view containing a sign-up form with fields for name, email, and password confirmation. Upon submission, the form triggers an Ajax request to the server. If the registration is successful, the user receives an on-screen confirmation message and an email with a verification link. Clicking that link activates the account and redirects the user to the login page. The forgot-password link opens a similar ExtJS window requesting the user’s email address and, on submission, sends a password reset email. The reset link in the email guides the user back to an ExtJS form where they can choose a new password. From either the login form or the reset form, users can return to the main onboarding page. Signing out at any time is as simple as clicking a log-out button in the application header, which invalidates their session and redirects them back to the login screen.

## Main Dashboard or Home Page
Once authenticated, the user sees the primary application viewport configured with an ExtJS BorderLayout. The top region holds a toolbar displaying the application title, a user menu with profile and sign-out options, and quick toggles for language and theme. On the left side, a collapsible TreePanel serves as the global navigation, listing modules such as Dashboard, Data Explorer, Reports, Settings, and, for administrators, a Users & Roles section. The center region presents a TabPanel where each module opens as a new tab. The bottom region contains a status bar that reports system messages and connectivity status. Users move from the main dashboard to any module by clicking items in the left-hand tree. Tabs can be closed and reopened, and the history manager ensures that browser back and forward buttons navigate between recently viewed tabs without a full page reload.

## Detailed Feature Flows and Page Transitions
When a user selects the Data Explorer module in the navigation tree, a new tab appears containing two panels arranged side by side. On the left is a configuration panel where users drag and drop fields from a field list into row and column drop zones. This panel also offers a choice of aggregation functions in a drop-down menu. On the right is an instance of Ext.grid.PivotGrid which reflects the configuration instantly. Hitting the Apply button triggers the pivot store to fetch data from the server and rebind to the grid view, updating totals and subtotals in real time. If the user clicks the Export button in the grid toolbar, the grid’s data is transformed and sent to the server for CSV generation. Download begins when the server responds.

In the Reports module, a standard GridPanel lists saved reports. Double-clicking a row opens an EditorGridPanel in a floating ExtJS window preloaded with report parameters. The user can modify filters, schedule the report, or delete it. Clicking Save sends an Ajax request to update the report on the server, upon which the grid refreshes to reflect any changes. If validation fails, the form highlights erroneous fields and displays an inline error message at the top.

The Settings module hosts multiple tabs within its own TabPanel. The first tab, Appearance, lets users select from available CSS themes in a ComboBox. Changing the theme triggers a call to Ext.util.CSS.swapStyleSheet, updating the look and feel without reloading the page. The second tab, Language, lists loaded locales discovered through PO files. Selecting a new language prompts the user with a modal confirmation built with Ext.MessageBox; confirming causes the application to reload resource strings and redraw visible components in the chosen language.

Administrators have access to a Users & Roles module. This opens a PropertyGrid that displays each user’s details when a name is selected in the user list. Roles and permissions are managed through a drag-and-drop interface into role buckets, and changes are saved via an Ajax action that returns success or failure feedback through a pop-up notification.

## Settings and Account Management
Access to personal settings is available at any time by clicking the user’s name in the top toolbar. This action opens a Profile window containing an Ext.form.Panel where users can update their display name, email address, and password. The form includes validation rules such as email format checks and password complexity requirements. After saving, the server responds with a confirmation message. Users can also configure notification preferences in a separate panel, toggling data-threshold alerts or scheduled report deliveries. All changes here are submitted together and, upon success, the application automatically returns the user to their previously active tab in the main dashboard.

## Error States and Alternate Paths
If a user enters invalid data into any form, the ExtJS VTypes validation routines highlight the offending fields and display tooltip-style error messages. Should an Ajax request fail due to network issues or server errors, a modal Ext.Msg.alert appears with a clear error title and message instructing the user to retry. While offline, the status bar in the dashboard turns red and disables actions that require a server connection. Attempting a restricted action, such as editing a user record without the necessary permissions, triggers an Ext.Msg.show dialog informing the user that access is denied. In each case, the user is given a retry or cancel option, and recovering from an error always returns them to the same form or view so they can correct inputs or try again.

## Conclusion and Overall App Journey
From the moment a new user lands on the onboarding page, through registration, password recovery, and signing in, Thejoflowers-KOS2 guides them into a richly interactive single-page application. The main dashboard provides immediate access to data exploration, reporting, and system administration via a unified navigation tree and a flexible tabbed workspace. Core features such as pivot grid analysis, form-driven editing, theming, and localization flow seamlessly from one to another. Users manage their account details and preferences in dedicated panels without losing context. Comprehensive validation and graceful error handling keep users informed and in control. By combining powerful ExtJS components, Ajax-driven interactions, and consistent feedback loops, the application supports both everyday tasks and advanced workflows in a clear, connected journey.
